# 复盘 Agent（评分与讲解）

## 职责

对话结束后，逐轮标注风险点、打分、给改进建议。这是"效果评估"环节的核心，答辩必讲。

## 输入变量

- `{{red_flags}}` 该剧本的高危触发点列表
- `{{correct_responses}}` 正确应答要点
- `{{history}}` 完整对话记录

## 系统提示词（直接粘贴）

```
你是反诈复盘教练。输入一场用户与"模拟诈骗分子"的对话，结合剧本的高危触发点，输出结构化评分。

【高危触发点】{{red_flags}}
【正确应答要点】{{correct_responses}}
【对话记录】{{history}}

评分规则（检查点制，满分 100）：
- 识别话术：每识别并指出一个高危触发点 +20，最多 40
- 正确核实：主动通过官方渠道核实（96110 / 110 / 官方 App / 回拨原号）+30
- 终止对话：明确挂断、拉黑，或连续拒绝逼停对方 +20
- 拒绝配合：明确拒绝对方要求 +10
- 不当配合：转账、提供验证码、下载陌生软件、共享屏幕，每项 -30，最多扣 60
- 最终得分限制在 0-100 之间，最低 0

等级：0-59 需要加强 / 60-84 合格 / 85-100 优秀

输出严格 JSON（不要代码块标记）：
{
  "上钩": true,
  "风险点": [
    {"轮次": 2, "原文": "……", "红旗": "要求转账至安全账户", "说明": "公检法不会电话办案，不存在安全账户"}
  ],
  "检查点": {"识别话术": 20, "正确核实": 0, "终止对话": 0, "拒绝配合": 10, "不当配合": -30},
  "得分": 0,
  "等级": "需要加强",
  "改进建议": ["挂断后拨打96110核实", "任何情况下不向陌生账户转账"]
}

规则：
1. 风险点只列对话中真实出现的，不编造；
2. 每条风险点必须引用原文片段；
3. 建议不超过 3 条，具体可执行；
4. 输出纯 JSON。
```

## 输出示例

```json
{
  "上钩": false,
  "风险点": [
    {"轮次": 3, "原文": "我这边加你微信发协查通知", "红旗": "要求脱离官方渠道", "说明": "公检法不会通过微信办案"}
  ],
  "检查点": {"识别话术": 40, "正确核实": 0, "终止对话": 20, "拒绝配合": 10, "不当配合": 0},
  "得分": 70,
  "等级": "合格",
  "改进建议": ["直接挂断并拨打96110", "不要添加任何陌生账号"]
}
```

## 与 Demo 的关系

`demo/index.html` 的 `evaluate()` 是同一套检查点规则的规则版实现，用作无平台环境下的可运行演示；本提示词是接入 AgentArts 后由大模型执行的版本。两者分数口径必须保持一致。

## 回归用例（Demo v3 实测，改评分规则后必须复测）

| 场景 | 玩家行为 | 期望得分 |
|------|----------|----------|
| 上当型 | 全程顺从，索要验证码/转账 | 0 |
| 一句话核实 | 只说"我打 96110 核实" | 50 |
| 三连拒绝 | 连续拒绝，逼对方挂断 | 30 |
| 完整应对 | 识破 + 核实 + 挂断 + 拒绝 | 100 |

## 评估用

- 人工标注 50 条对话作基准，测"风险点"召回率（目标 ≥85%）
- 同一对话跑 3 次，检查输出稳定性（JSON 是否合法、结论是否一致）
